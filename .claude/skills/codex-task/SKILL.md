# codex-task — Codex 위임 프롬프트 생성

Claude Code의 **설계→위임** 역할을 고정하는 스킬이다.
구현할 작업을 받아 Codex CLI용 프롬프트를 만들어 **사용자에게 출력**한다.

## 절대 규칙

- **코드를 작성하지 않는다.** 구현 파일을 만들거나 수정하지 않는다.
- **Codex를 직접 실행하지 않는다.** 결과물은 사용자가 복사해 Codex CLI에 붙여넣을 텍스트다.
- 미확정 기술(백엔드·프론트·배포)을 임의로 결정하지 않는다. `TBD`로 남긴다.

## 절차

1. **작업 식별** — 인자/대화에서 무엇을 구현할지 한 문장으로 좁힌다. 모호하면 먼저 사용자에게 질문한다.
2. **순서 확인** — `docs/design-docs/rag-design.md` §7의 파이프라인 구현 순서(시드 스키마→임베딩→인덱싱→검색→거리정규화→스코어링→프롬프트조립→생성→평가)에서 이 작업의 위치를 확인한다. 선행 단계가 안 끝났으면 사용자에게 알린다.
3. **제약 추출** — 관련 docs를 읽어 반드시 지킬 제약을 뽑는다:
   - `docs/product-specs/project-brief.md` — MVP 범위, 제외 범위, 신뢰성 원칙
   - `docs/design-docs/architecture.md` — 모듈 경계, 설정 주입 표(환경변수)
   - `docs/design-docs/rag-design.md` — 스코어링·생성 명세 (RAG 관련일 때)
   - `docs/references/data-policy.md`(정책) / `docs/design-docs/data-design.md`(스키마 정본) — 데이터 관련일 때
   - `AGENTS.md` — 구현 규칙, 완료 조건, 에스컬레이션 기준
4. **완료 조건 정의** — 테스트 통과 기준, 갱신할 문서, 검증 항목을 명시한다.
5. **출력** — 아래 형식 그대로 코드블록으로 출력한다.

## 출력 형식 (CLAUDE.md 위임 프로토콜)

```
## 목표
[무엇을 구현할지 한 문장]

## 대상 파일·모듈
[생성하거나 수정할 파일 목록 — architecture.md 모듈 경계 기준]

## 제약 조건
[project-brief.md 기준 반드시 지킬 사항]
[AGENTS.md의 해당 구현 규칙 — 추상화 계층, 설정 주입, 0-1 정규화, 출처 충실성 등 작업에 해당하는 것]

## 완료 조건
[pytest 통과 기준 / 갱신할 docs / score·시드 ID 등 검증 항목]

## 참고 문서
[Codex가 읽어야 할 docs/ 파일 목록]
```

## 마무리

출력 후, 사용자에게 (1) 이 프롬프트를 Codex에 넘기면 되고 (2) 결과가 나오면 `/review-codex`로 리뷰하면 된다고 한 줄로 안내한다.

# review-codex — Codex 결과 리뷰 오케스트레이터

Claude Code의 **리뷰** 역할을 고정하는 스킬이다.
두 전담 리뷰어를 병렬로 돌리고 결과를 종합해 통과/수정 판정을 낸다.

## 절차

1. **변경 수집** — 인자로 파일·커밋·PR이 지정되면 그것을, 아니면 `git status`·`git diff`·`git diff --staged`로 변경 범위를 파악한다. 변경이 없으면 사용자에게 대상이 무엇인지 묻는다.

2. **병렬 리뷰 호출** — `spec-reviewer`와 `rag-reviewer`를 **한 메시지에서 두 개의 Agent 호출로 동시에** 실행한다. 각 호출에 검토 대상(파일 목록 또는 diff 범위)을 명확히 전달한다.
   - `spec-reviewer`: 기획·아키텍처 준수 (모듈 경계, 추상화, 하드코딩, TBD, 문서 동기화, brief 충돌)
   - `rag-reviewer`: RAG 정확성·신뢰성 (0-1 정규화·가중합, 출처 충실성, 데이터 정책, 테스트)

3. **종합** — 두 리뷰어 결과를 `CLAUDE.md` 리뷰 체크리스트 4영역(설계 준수 / 스코어링 / 데이터·신뢰성 / 테스트·문서)으로 합친다. 중복은 합치고, severity(blocker > warning > nit)로 정렬한다.

4. **판정**:
   - blocker가 하나도 없으면 **통과** — 다음으로 `python -m pytest` 실행 또는 `/verify`를 권한다.
   - blocker가 있으면 **수정 필요** — 아래 형식으로 Codex 재위임 프롬프트 초안을 만든다 (codex-task 형식 재사용).

## 출력 형식

```
## 리뷰 종합 판정: 통과 | 수정 필요

### blocker
- <파일:라인> 내용 (출처: spec-reviewer / rag-reviewer)

### warning
- ...

### nit
- ...

### CLAUDE.md 체크리스트 요약
- 설계 준수: 통과/실패 + 핵심 사유
- 스코어링: ...
- 데이터·신뢰성: ...
- 테스트·문서: ...
```

수정 필요 시 이어서:

```
## Codex 재위임 프롬프트 (수정용)
## 목표 / 대상 파일·모듈 / 제약 조건 / 완료 조건 / 참고 문서
```

## 절대 규칙

- 리뷰는 읽기 전용이다. 이 스킬 실행 중 구현 코드를 수정하지 않는다.
- 수정은 Codex에 위임하는 게 기본이다. 사용자가 명시적으로 "직접 고쳐줘"라고 할 때만 예외.

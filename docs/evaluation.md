# Evaluation Guide

> **목적**: RAG 추천 품질을 평가하는 기준, 방법, 체크리스트를 정의한다.
> 평가 항목 목록은 [`rag-evaluation.md`](rag-evaluation.md)와 상호 보완 관계다.
> 이 문서는 **방법론과 비교 절차**에 집중한다.

---

## 1. 평가 목표

웹 UI 품질이 아니라 **RAG 파이프라인이 올바르게 작동하는가**를 확인한다.

| 평가 축 | 질문 |
|---------|------|
| 분위기 의도 매칭 | 사용자의 자연어 의도에 맞는 장소가 상위에 오는가 |
| 거리 제약 반영 | 너무 먼 장소가 상위에 오지 않는가 |
| 출처 충실성 | 추천 이유가 시드 근거 안에 머무는가 |
| 환각 여부 | 시드에 없는 사실이 생성 결과에 포함되지 않는가 |
| 재현 가능성 | 같은 쿼리에 같은 순서의 결과가 나오는가 |

## 2. 평가 레이어

### Layer 1 — 시드 검증 (자동화 가능)

인덱싱 전에 시드 레코드의 형식과 내용을 검사한다.

| 항목 | 기준 |
|------|------|
| 필수 필드 존재 | `place_id`, `name`, `address`, `latitude`, `longitude`, `atmosphere_text`, `attributes`, `source` |
| 좌표 유효 범위 | 위도 33–39, 경도 124–132 |
| `atmosphere_text` 최소 길이 | 50자 이상 |
| `source` 존재 | 출처 없는 시드 인덱싱 거부 |
| `place_id` 고유성 | 중복 ID 없음 |

### Layer 2 — 검색 품질 평가 (수동 + 자동)

고정 쿼리 fixture로 검색 결과를 평가한다.

**기본 테스트 쿼리**:

| 쿼리 | 기대 동작 |
|------|-----------|
| "조용히 이야기하기 좋은 카페" | `noise_level: 조용함`, "대화하기 좋음" 표현이 있는 시드가 상위에 등장 |
| "단체로 앉기 좋은 식당" | `seating_type: 단체석` 또는 "단체" 표현이 있는 시드가 상위에 등장 |
| "역에서 너무 멀지 않은 저녁 장소" | 중간지점 1km 이내 시드가 상위에 등장 |
| "분위기는 좋지만 시끄럽지 않은 곳" | `noise_level: 조용함/보통` 시드가 `시끄러움` 시드보다 상위에 등장 |

**검색 결과 확인 항목**:
- top-k 후보의 `place_id`, `name`.
- `atmosphere_score`, `distance_score`, `final_score` 각각 출력되는가.
- 가중치 변경 시 순위가 기대대로 변하는가.

### Layer 3 — 하이브리드 스코어링 검증 (자동화 권장)

```python
# pytest 예시 구조
def test_closer_venue_wins_when_distance_weight_high():
    """거리 가중치가 높으면 가까운 시드가 먼 시드보다 높은 순위를 가져야 한다."""

def test_atmosphere_score_dominates_when_weight_high():
    """분위기 가중치가 높으면 분위기 매칭이 낮은 가까운 시드보다
    분위기 매칭이 높은 먼 시드가 더 높은 순위를 가져야 한다."""

def test_distance_score_normalization():
    """거리 점수는 0–1 범위여야 한다. MAX_DISTANCE_KM 이상이면 0."""

def test_final_score_within_range():
    """final_score는 항상 0–1 범위여야 한다."""
```

### Layer 4 — 출처 충실성 평가 (수동)

LLM이 생성한 추천 이유를 시드 원문과 대조한다.

| 항목 | 확인 방법 |
|------|-----------|
| 모든 claim이 추적 가능한가 | 생성 문장의 각 주장을 `atmosphere_text` 또는 `attributes`에서 찾기 |
| 근거 없는 주장이 없는가 | 시드에 없는 정보(주차 가능, 예약 필수 등)가 언급되면 실패 |
| 근거 시드 ID가 명시되는가 | 각 추천에 `seed_ids`가 포함되어 있는가 |

### Layer 5 — 환각(Hallucination) 평가 (수동)

생성 결과에서 다음을 확인한다.

- 존재하지 않는 장소 이름·주소 언급 여부.
- 시드에 없는 서비스(발렛, 키즈존 등) 언급 여부.
- 과장된 표현("서울 최고의 카페") 여부.

모델 품질이 애매한 경우에도 환각은 허용하지 않는다. 시드 제약 프롬프트를 강화한다.

## 3. 임베딩 모델 비교 방법

파이프라인 완성 후 임베딩 모델을 교체해 비교하는 절차.

### 비교 대상

| 모델 | 상태 |
|------|------|
| `dragonkue/snowflake-arctic-embed-l-v2.0-ko` | 현재 기본값 |
| `BAAI/bge-m3` | 비교 후보 |
| 기타 | 한국어 임베딩 리더보드 참고 |

### 비교 절차

1. **동일 시드로 두 인덱스 생성**: 모델 A용 Chroma 인덱스, 모델 B용 Chroma 인덱스.
2. **동일 테스트 쿼리 실행**: Layer 2의 기본 테스트 쿼리 4개 이상.
3. **결과 비교**:
   - top-5 후보가 동일한가, 순위가 바뀌는가.
   - 분위기 매칭 직관이 더 잘 반영된 모델은 어느 쪽인가.
4. **수동 판정**: "조용히 이야기하기 좋은 카페" 쿼리에서 어느 모델이 더 적절한 시드를 상위에 올렸는가.

## 4. 생성 LLM 비교 방법

### 비교 대상

| 모델 | 상태 |
|------|------|
| `Qwen/Qwen3-4B-Instruct-2507` | 현재 기본값 |
| `google/gemma-3-4b-it` | 비교 후보 |
| EXAONE 계열 | 한국 특화 후보 |

### 비교 절차

1. **동일 시드·쿼리·검색 결과로 생성**: 검색 단계를 고정하고 생성 단계만 교체.
2. **평가 기준**:

| 기준 | 설명 |
|------|------|
| 한국어 자연스러움 | 문장이 어색하지 않은가 |
| 출처 충실성 | 시드 외 정보를 지어내지 않는가 |
| 근거 연결 | seed_id를 명시하는가 |
| 간결성 | 불필요한 반복·장황함 없이 핵심만 전달하는가 |

3. **같은 프롬프트로 3–5개 쿼리 비교 후 모델 선택**.

## 5. 수동 평가 체크리스트

추천 결과를 한 사람이 직접 확인할 때 사용하는 체크리스트.

### 검색 품질

- [ ] top-5 결과가 분위기 쿼리와 직관적으로 맞는가?
- [ ] 너무 먼 장소(3km 이상)가 상위에 오지 않는가?
- [ ] 가중치를 바꿨을 때 순위가 기대대로 변하는가?
- [ ] 세 점수(atmosphere, distance, final)가 결과에 출력되는가?

### 생성 품질

- [ ] 추천 이유가 시드 원문과 일치하는가?
- [ ] 근거 없는 주장이 없는가?
- [ ] 근거 시드 ID가 명시되어 있는가?
- [ ] 문장이 자연스러운 한국어인가?
- [ ] 환각(없는 정보 생성)이 없는가?

### 전체 파이프라인

- [ ] 같은 쿼리를 두 번 실행하면 같은 결과가 나오는가?
- [ ] 인덱싱 명령이 오류 없이 실행되는가?
- [ ] 쿼리 하네스 실행 시 점수 구성 요소가 출력되는가?

## 6. 평가 통과 기준

| 기준 | 통과 조건 |
|------|-----------|
| 시드 검증 | 전체 시드가 검증 통과 (오류 0개) |
| 검색 재현성 | 동일 쿼리에 동일 결과 (결정적 실행) |
| 점수 출력 | 모든 결과에 세 점수 포함 |
| 출처 충실성 | 모든 claim이 시드로 추적 가능 |
| 환각 없음 | 시드 외 정보 생성 0건 |
| 근거 명시 | 각 추천에 seed_id 포함 |

# Documentation Structure

`project-brief.md` is the source of truth for product scope, RAG strategy, data constraints, and implementation order.

- `architecture.md`: RAG harness architecture and module boundaries.
- `data-policy.md`: accepted data sources, seed rules, and forbidden data usage.
- `rag-evaluation.md`: retrieval, scoring, and generation evaluation criteria.
- `agent-workflow.md`: Codex workflow, implementation order, and done checklist.
- `prompts/recommendation-system.md`: grounded recommendation generation prompt.

Do not redefine project direction in a new document without updating `project-brief.md` or linking the change back to it.
